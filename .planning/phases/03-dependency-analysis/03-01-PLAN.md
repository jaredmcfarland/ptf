1. **&lt;role&gt;**
   - You are a PTF dependency analyzer
   - Transform decomposed tasks into executable plan by inferring dependencies
   - Job: produce dependency graph + wave assignments with no cycles

2. **&lt;philosophy&gt;**
   Three core principles:
   - Automatic Inference: Dependencies derived from task I/O, not declared
   - Parallelism First: Maximize tasks per wave while respecting dependencies
   - Confidence Levels: HIGH for exact matches, MEDIUM for patterns, LOW for heuristics

3. **&lt;execution_flow&gt;** with 7 steps:

   **step name="load_tasks" priority="first"**
   - Read all task files from .orchestrator/decomposition/tasks/
   - Read config.yaml to get domain
   - Load adapters/{domain}.yaml for inference hints and common_patterns
   - Build task index: id -> {inputs, outputs, description, context_notes}

   **step name="pass1_artifact"**
   - **Artifact Matching (HIGH confidence)**
   - For each task B's inputs:
     - Find tasks whose outputs contain that input path (exact match)
     - Create dependency: {from: producer, to: consumer, type: "artifact", confidence: "high"}
   - Most reliable inference source

   **step name="pass2_type"**
   - **Type/Pattern Matching (MEDIUM confidence)**
   - For inputs with glob patterns (*, **):
     - Match against output paths using glob semantics
     - Create dependency if not already exists
   - Uses minimatch-style patterns

   **step name="pass3_semantic"**
   - **Semantic Analysis (MEDIUM confidence)**
   - Analyze task descriptions for implicit references:
     - "uses the X from..."
     - "after Y is complete..."
     - "builds on..."
     - "references the schema/model/service from..."
   - Only add if not captured by artifact matching
   - Mark as confidence: "medium"

   **step name="pass4_heuristic"**
   - **Domain Heuristics (LOW confidence)**
   - Load adapter's dependencies.common_patterns
   - For each pattern (e.g., "test depends on source-code"):
     - Match tasks by output artifact type
     - Create dependency only if no existing dependency between tasks
   - Mark as confidence: "low"

   **step name="pass5_resource"**
   - **Resource Conflict Detection (HIGH confidence)**
   - Find tasks with overlapping outputs (same file path)
   - These CANNOT run in parallel (would cause conflicts)
   - Create resource dependency, order by task ID (alphabetical)
   - Mark as type: "resource", confidence: "high"

   **step name="detect_cycles"**
   - Run Tarjan's algorithm to find strongly connected components
   - If any SCC has >1 member, cycles exist
   - For each cycle:
     - List all tasks in cycle
     - Find dependency with lowest confidence
     - Suggest breaking that dependency
   - If cycles found: return ANALYSIS BLOCKED
   - If no cycles: continue to wave computation

   **step name="compute_waves"**
   - Run Kahn's algorithm:
     1. Initialize in-degree for each task (count of incoming dependencies)
     2. Find all tasks with in-degree 0 (wave 1)
     3. Create wave, remove tasks from graph
     4. Decrement in-degrees of dependent tasks
     5. Repeat until all tasks assigned
   - Each iteration produces one wave
   - Tasks in same wave can execute in parallel

   **step name="write_output"**
   - Write .orchestrator/decomposition/graph.yaml with structure:
   ```yaml
   step: 5-dependency-graph
   created: {timestamp}
   status: complete
   task_count: {N}

   dependencies:
     - from: {task-id}
       to: {task-id}
       type: {artifact|semantic|resource|implicit}
       confidence: {high|medium|low}
       reason: "{explanation}"

   waves:
     - number: 1
       tasks: [task-ids]
       depends_on_waves: []
       rationale: "No dependencies - can start immediately"
     - number: 2
       tasks: [task-ids]
       depends_on_waves: [1]
       rationale: "Depend on wave 1 tasks"

   validation:
     has_cycles: false
     total_dependencies: {N}
     high_confidence: {count}
     medium_confidence: {count}
     low_confidence: {count}

   warnings:
     - "{any low-confidence dependencies flagged}"
   ```

4. **&lt;structured_returns&gt;**
   Two formats:
   - ANALYSIS COMPLETE: dependencies count, wave summary, parallelism factor, files created, next steps
   - ANALYSIS BLOCKED: cycle details, tasks in cycle, suggested dependency to break

<algorithms>
**Graph Algorithms for Dependency Analysis**

## Tarjan's Algorithm - Cycle Detection

Finds all strongly connected components (SCCs). Any SCC with >1 member is a cycle.

```python
def tarjan_scc(tasks, dependencies):
    """
    Returns: {
        "has_cycles": bool,
        "cycles": [[task_ids in cycle]],
        "resolution_hints": [{"cycle": [...], "suggested_break": dep, "reason": str}]
    }
    """
    # Build adjacency list
    adj = {t.id: [] for t in tasks}
    for dep in dependencies:
        adj[dep.from].append(dep.to)

    index_counter = [0]  # Mutable container for nonlocal
    stack = []
    lowlinks = {}
    indices = {}
    on_stack = {}
    sccs = []

    def strongconnect(v):
        indices[v] = index_counter[0]
        lowlinks[v] = index_counter[0]
        index_counter[0] += 1
        stack.append(v)
        on_stack[v] = True

        for w in adj[v]:
            if w not in indices:
                strongconnect(w)
                lowlinks[v] = min(lowlinks[v], lowlinks[w])
            elif on_stack.get(w, False):
                lowlinks[v] = min(lowlinks[v], indices[w])

        # If v is a root node, pop the SCC
        if lowlinks[v] == indices[v]:
            scc = []
            while True:
                w = stack.pop()
                on_stack[w] = False
                scc.append(w)
                if w == v:
                    break
            sccs.append(scc)

    for task in tasks:
        if task.id not in indices:
            strongconnect(task.id)

    # Find cycles (SCCs with >1 member)
    cycles = [scc for scc in sccs if len(scc) > 1]

    if not cycles:
        return {"has_cycles": False}

    # Generate resolution hints
    hints = []
    for cycle in cycles:
        # Find deps within this cycle
        cycle_deps = [d for d in dependencies
                      if d["from"] in cycle and d["to"] in cycle]

        # Find lowest confidence dep
        confidence_order = {"low": 0, "medium": 1, "high": 2}
        lowest = min(cycle_deps,
                     key=lambda d: confidence_order.get(d["confidence"], 1))

        hints.append({
            "cycle": cycle,
            "suggested_break": lowest,
            "reason": f"This dependency has {lowest['confidence']} confidence"
        })

    return {
        "has_cycles": True,
        "cycles": cycles,
        "resolution_hints": hints
    }
```

## Kahn's Algorithm - Wave Computation

Topological sort that naturally groups tasks into parallel waves.

```python
def kahn_waves(tasks, dependencies):
    """
    Returns: [
        {"number": 1, "tasks": [ids], "depends_on_waves": []},
        {"number": 2, "tasks": [ids], "depends_on_waves": [1]},
        ...
    ]
    """
    # Build in-degree map and adjacency list
    in_degree = {t.id: 0 for t in tasks}
    dependents = {t.id: [] for t in tasks}

    for dep in dependencies:
        in_degree[dep["to"]] += 1
        dependents[dep["from"]].append(dep["to"])

    waves = []
    remaining = set(t.id for t in tasks)

    while remaining:
        # Find all tasks with no unmet dependencies
        ready = [t for t in remaining if in_degree[t] == 0]

        if not ready and remaining:
            # This shouldn't happen if cycles were detected first
            raise Exception("Cycle detected - run Tarjan's first")

        # Create wave
        wave_number = len(waves) + 1
        wave = {
            "number": wave_number,
            "tasks": ready,
            "status": "pending",
            "depends_on_waves": [wave_number - 1] if wave_number > 1 else [],
            "rationale": "No dependencies" if wave_number == 1
                         else f"Depend on wave {wave_number - 1} tasks"
        }
        waves.append(wave)

        # Remove tasks from remaining, decrement dependents' in-degrees
        for task_id in ready:
            remaining.remove(task_id)
            for dependent_id in dependents[task_id]:
                in_degree[dependent_id] -= 1

    return waves
```

## Parallelism Factor

```python
def compute_parallelism(tasks, waves):
    """
    Parallelism factor = total_tasks / wave_count
    Higher is better (more tasks can run in parallel)

    1.0 = fully sequential (no parallelism)
    N = N tasks can run simultaneously on average
    """
    if not waves:
        return 0
    return len(tasks) / len(waves)
```

**Example:**
- 8 tasks, 4 waves = 2.0x parallelism
- 8 tasks, 8 waves = 1.0x (fully sequential)
- 8 tasks, 2 waves = 4.0x (high parallelism)

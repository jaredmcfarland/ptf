**Required frontmatter:**
```yaml
---
name: ptf-decomposer
description: Executes 5-step decomposition process transforming goals into atomic tasks
tools: Read, Write, Bash, Glob, Grep
---
```

**Required sections:**

1. **&lt;role&gt;**
   - You are a PTF decomposer
   - Transform analyzed goals into validated atomic tasks
   - Job: produce atomic tasks with 100% coverage and no overlap

2. **&lt;philosophy&gt;**
   Three core principles:
   - Fresh Context is King: Every task completable by fresh agent
   - Atomicity is Non-Negotiable: Apply criteria at every recursion level
   - 100% Rule from WBS: Complete coverage, no gaps, no extras

3. **&lt;execution_flow&gt;** with 5 steps:

   **step name="load_context" priority="first"**
   - Read analysis.yaml, constitution.yaml
   - Load adapters/{domain}.yaml
   - Extract objective, scope, success_criteria
   - Extract decomposition heuristics and atomicity criteria

   **step name="step2_subgoals"**
   - Apply domain heuristics to break goal into major components
   - For software: consider by-layer, by-feature cuts
   - Write .orchestrator/decomposition/subgoals.yaml
   - Validate 100% coverage before proceeding
   - YAML structure: step, created, status, subgoals array

   **step name="step3_decompose"**
   - For each subgoal, evaluate against atomicity criteria
   - If atomic: create task YAML in .orchestrator/decomposition/tasks/
   - If not atomic: break into sub-subgoals, recurse
   - Task YAML structure: id, name, from_subgoal, description, inputs, outputs, verify, context_notes, context_budget, on_failure
   - Continue until all leaves are atomic

   **step name="step4_validate"**
   - Run validation checks:
     1. Coverage: tasks cover all success_criteria?
     2. Overlap: duplicate outputs between tasks?
     3. Atomicity: all tasks meet all criteria?
     4. Input Coverage: every input has a producer?
     5. Output Usefulness: every output consumed or final?
   - Write .orchestrator/decomposition/validation.yaml
   - If failed: return DECOMPOSITION BLOCKED
   - If passed: continue to step 5

   **step name="step5_graph"**
   - Build initial dependency graph from task inputs/outputs
   - Write .orchestrator/decomposition/graph.yaml
   - Note: Full inference happens in Phase 3

4. **&lt;structured_returns&gt;**
   Two formats:
   - DECOMPOSITION COMPLETE: tasks count, coverage status, subgoal structure table, files created, next steps
   - DECOMPOSITION BLOCKED: issue category, issues table, what's awaiting

**Implementation notes:**
- Each step writes state files immediately (resume capability)
- Use status field: "in_progress" at start, "complete" at end
- Reference 02-RESEARCH.md for exact YAML schemas
- Follow gsd-executor.md pattern for structured returns

   ```

2. **Apply each criterion:**

   | Criterion | Check | Pass/Fail |
   |-----------|-------|-----------|
   | single-file | outputs.length <= 3 | |
   | fresh-context-completable | estimated_input_tokens < 60000 | |
   | verifiable | verify.length > 0 | |
   | focused | description covers one concept | |
   | explicit-inputs | all referenced files in inputs | |

3. **If ANY criterion fails:**
   - Log which criterion failed
   - Break task into smaller pieces
   - Recurse on each piece
   - Check recursion depth (max from adapter)

4. **If ALL criteria pass:**
   - Create task YAML file
   - Add to tasks list
   - Mark subgoal portion as covered

**Recursion depth guard:**
```python
if current_depth >= adapter.decomposition.max_recursion_depth:

- Task touches multiple files but they're tightly coupled (e.g., component + styles) -> Allow 2-3 files
- Task seems large but is actually simple (e.g., config file) -> Check context estimate
- Task could be split but splits would be too interdependent -> Keep together
</atomicity_evaluation>
```

**Step 4 runs these checks on the complete task set:**

```python
for criterion in analysis.success_criteria:
    matching_tasks = [t for t in tasks if criterion in t.coverage_mapping]
    if not matching_tasks:
        issues.append({
            "type": "gap",
            "severity": "error",
            "description": f"No task covers: {criterion}"
        })
```

## Check 2: Overlap

Verify no two tasks produce the same output.

```python
all_outputs = {}
for task in tasks:
    for output in task.outputs:
        if output.path in all_outputs:
            issues.append({
                "type": "overlap",
                "severity": "error",
                "description": f"Both {all_outputs[output.path]} and {task.id} produce {output.path}"
            })
        all_outputs[output.path] = task.id
```

## Check 3: Atomicity

Verify every task passes all atomicity criteria.

```python
for task in tasks:
    for criterion in adapter.atomicity_criteria:
        if not passes_criterion(task, criterion):
            issues.append({
                "type": "too_large",
                "severity": "error",
                "task": task.id,
                "criterion": criterion.criterion,
                "reason": criterion.fail_signal
            })
```

## Check 4: Input Coverage

Verify every task input either:
- Is produced by another task, OR
- Is marked as external (required: false with exists_external: true)

```python
produced = {o.path for t in tasks for o in t.outputs}
for task in tasks:
    for inp in task.inputs:
        if inp.required and inp.path not in produced:
            if not file_exists(inp.path):
                issues.append({
                    "type": "missing_producer",
                    "severity": "error",
                    "task": task.id,
                    "input": inp.path
                })
```

## Check 5: Output Usefulness

Verify every output is either:
- Consumed by another task, OR
- Is a final deliverable (success criterion artifact)

```python
consumed = {i.path for t in tasks for i in t.inputs}
final_outputs = [criterion artifacts from success_criteria]

for task in tasks:
    for output in task.outputs:
        if output.path not in consumed and output.path not in final_outputs:
            issues.append({
                "type": "unused_output",
                "severity": "warning",
                "task": task.id,
                "output": output.path
            })
```

**Validation result:**
- All checks pass with no errors -> status: passed
- Any error issues -> status: failed
- Only warnings -> status: passed (warnings logged)
</validation_checks>

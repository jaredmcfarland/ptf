**Required frontmatter:**
```yaml

name: ptf:init
```

**Required sections:**

1. **&lt;objective&gt;**
   - Initialize PTF project by analyzing goal
   - Lists files created: config.yaml, goal.md, analysis.yaml, constitution.yaml
   - Notes "After this command: Run /ptf:decompose"

2. **&lt;execution_context&gt;**
   - Reference @.claude/skills/ptf/SKILL.md

3. **&lt;context&gt;**
   - Goal: $ARGUMENTS

4. **&lt;process&gt;** with 7 phases:

   **Phase 1: Setup**
   - Create .orchestrator/decomposition directory
   - Check for existing project (abort if exists)

   **Phase 2: Domain Detection**
   - Analyze goal text keywords to guess domain
   - Load adapter from adapters/{domain}.yaml
   - If uncertain, ask user with AskUserQuestion

   **Phase 3: Goal Clarification**
   - Use AskUserQuestion with adapter's questioning.init_questions
   - Process each question category from adapter
   - Capture user decisions

   **Phase 4: Goal Analysis**
   - Write .orchestrator/goal.md (immutable, original text)
   - Write .orchestrator/decomposition/analysis.yaml with:
     - step: 1-goal-analysis
     - created: timestamp
     - status: complete
     - objective, scope (included/excluded), constraints, success_criteria, domain

   **Phase 5: Constitution Generation**
   - Load adapter's constitution.template
   - Apply gathered constraints to template
   - Write .orchestrator/decomposition/constitution.yaml

   **Phase 6: Commit**
   - git add .orchestrator/
   - git commit with goal one-liner

   **Phase 7: Complete**
   - Present summary
   - Show next step: /ptf:decompose

5. **&lt;success_criteria&gt;**
   - Checklist of all required outputs

**Implementation notes:**
- Follow GSD new-project.md pattern for multi-phase process
- Use AskUserQuestion for user interaction (not inline questions)
- Write files immediately after each phase (don't batch at end)
- Include clear step-by-step bash commands

Reference 02-RESEARCH.md code examples for exact YAML structures.

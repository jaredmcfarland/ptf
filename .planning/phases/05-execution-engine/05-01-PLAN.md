Create the task executor subagent following the structure from 05-RESEARCH.md.

**Requirements to implement:**
- EXEC-04: Fresh context dispatch (load only declared inputs)
- EXEC-05: Context loading from declared inputs only
- EXEC-06: Task executor subagent
- EXEC-08: Ralph-style execution (repeat until verified)
- EXEC-09: Completion promise pattern (VERIFICATION PASSED phrase)
- EXEC-10: Configurable max iterations

**Structure:**

1. **Frontmatter:**
   - name: ptf-executor
   - description: Executes single PTF task with fresh context and verification
   - tools: Read, Write, Bash, Glob, Grep

2. **Role section:**
   - Task execution with fresh context
   - Input: task definition, declared inputs, outputs expected, verification criteria
   - Output: VERIFICATION PASSED or BLOCKED signal

3. **Philosophy section:**
   - Fresh context is king (no accumulated state)
   - Task boundary enforcement (don't do extra work)
   - Verification before claiming completion

4. **Execution flow with steps:**
   - step: understand - Parse task definition, understand scope
   - step: load_inputs - Read only declared input files
   - step: execute - Implement task as described
   - step: verify - Run verification steps
   - step: signal - Output completion phrase

5. **Ralph-style iteration logic:**
   - Track iteration count (passed in or from config)
   - On verification failure: log and prepare for next iteration
   - On max iterations: output BLOCKED with reason
   - Fresh context per iteration (no memory of previous attempts)

6. **Completion protocol section:**
   - VERIFICATION PASSED: Output when all verifications pass
   - BLOCKED: [reason]: Output when cannot proceed
   - Clear instructions on when to output each

7. **Structured returns:**
   - VERIFICATION PASSED format
   - BLOCKED format with reason categories:
     - missing_input: Required file not found
     - verification_failed: Output exists but verification fails
     - execution_error: Error during task execution
     - max_iterations: Exhausted retry attempts

Follow the pattern established by ptf-decomposer.md and ptf-state-manager.md:
- Use XML step tags with name attribute
- Include philosophy section
- Provide structured return formats
- Document all inputs/outputs clearly
